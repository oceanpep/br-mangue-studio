# Software test and benchmark records

Keep dated records when adding measurements; retain earlier evidence with its
original version, inputs, measurement scope, and limitations. Timing from
one configuration or computer must not be relabelled as a measurement of a
later release.

| Record | Scope |
| --- | --- |
| [Linux island pilot](ILHA_LINUX_20261001.md) | Continuous/block equivalence and annual raster outputs; original pilot extent |
| [Linux pilot data](ILHA_LINUX_2025_2100.json) | Machine-readable measurements for the original Linux pilot |
| [Archived Windows CMMA runs](CMMA_WINDOWS_2024_2100_20261001.md) | Historical descriptive timings; different class mappings prevent an engine-equivalence inference |

See the [reproducibility protocol](../REPRODUCIBILITY_AND_BENCHMARKING.md)
for time scopes, resource counters, comparison rules, and how to add a new
record. Reports establish software operation for the stated inputs and
parameters; ecological validation requires independent observations.

Version 1.4.0 includes periodic resource observations when calculating the
reported RSS peak. Earlier peak summaries can refer to annual checkpoints;
check the record's measurement scope before comparing memory values.
