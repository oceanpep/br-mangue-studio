How the Studio scales across the CMMA.

A reproducible comparison of continuous and persistent-block processing using the complete CMMA land-cover grid and ANADEM elevation data between Pará and Maranhão, Brazil.

The benchmark covers one annual transition from 2024 to 2025 across the complete CMMA grid. Each engine was run once with the same inputs and parameters; annual GeoTIFF snapshots were disabled so the comparison measures simulation work rather than export time.

Input and scenario

CMMA V2 database land-cover band for 2024, plus the matching ANADEM 30 m elevation blocks covering the full study area. Tide influence: 6.0 m. Sea-level rise: 0.3 mm/year. Soil/suitability layer disabled; migration fallback enabled.

What the check tells us

The two engines produced byte-identical final GeoTIFFs and identical annual trajectories. This verifies implementation equivalence and gives a transparent performance reference; it is not an ecological validation or a universal hardware limit.

Host used for the measurement: Intel Core i3-1215U with 19.7 GiB total RAM. Scaling the recorded 78.007-million-cell footprint to 80 million cells gives a first-order estimate of 6.1 GiB after a step. The continuous step also creates a transient previous-state snapshot of about 0.7 GiB, so a practical planning figure is roughly 6.8 GiB before application overhead; reserve 8–10 GiB free. A 100-step scenario reuses these arrays—RAM does not become 100 times larger—while elapsed time is expected to scale to about 3.4 hours continuously or 13.2 hours in blocks if per-step cost remains stable. Annual state rasters increase storage use, not resident RAM. For this CMMA grid, continuous is the correct choice on a machine with that headroom: it is faster because it keeps state in RAM and avoids persistent I/O. Blocks is not expected to be faster; its justification is capacity and recovery for domains that no longer fit safely in memory, including very large macro-tidal Amazon coastal studies. In version 1.0.0, however, the loader still materializes the full input grid during setup, so this benchmark's 10.01 GiB block peak is not yet a lower-RAM guarantee. Actual times and memory vary with CPU load, storage, output settings, and raster size.
